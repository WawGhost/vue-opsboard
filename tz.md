# Какие именно mock-данные нужны

## 1. `zones`

5–8 зон города / региона

```ts
type Zone = {
  id: string
  name: string
  polygon: Array<{ x: number; y: number }>
  loadFactor: number
  trafficLevel: number
}
```

**Зачем:**
нужны для карты, heatmap, фильтров, инцидентов, аналитики по регионам.

---

## 2. `vehicles`

20–40 единиц транспорта.

Нужно разнообразие:

* разные типы;
* разные статусы;
* разная грузоподъемность;
* разные зоны;
* часть транспорта свободна, часть занята, часть сломана.

**Зачем:**
чтобы карта, список, фильтры и симуляция выглядели живыми.

---

## 3. `tasks`

50–150 задач доставки.

У задач должны быть:

* дедлайны;
* приоритеты;
* зоны;
* объем;
* ETA;
* риск просрочки;
* назначение на транспорт или отсутствие назначения.

**Зачем:**
это основная “рабочая” сущность, вокруг которой строится принятие решений.

---

## 4. `incidents`

10–20 инцидентов разных типов.

Примеры:

* traffic in Zone B from 13:00 to 14:30;
* van #14 breakdown at 16:20;
* order spike in downtown at 18:00;
* warehouse outgoing slowdown.

**Зачем:**
без них симулятор будет плоским.

---

## 5. `analytics snapshots`

Нужен массив исторических точек для графиков и replay.

```ts
type AnalyticsPoint = {
  timestamp: string
  completed: number
  delayed: number
  avgEta: number
  activeIncidents: number
  utilization: number
}
```

**Зачем:**
графики, таймлайн, режим воспроизведения.

---

## 6. `scenario snapshots`

Для replay полезно иметь не только текущий state, но и историю.

```ts
type ScenarioSnapshot = {
  timestamp: string
  vehicles: Array<{
    id: string
    position: { x: number; y: number }
    status: string
    load: number
    currentTaskId: string | null
  }>
  tasks: Array<{
    id: string
    status: string
    assignedVehicleId: string | null
  }>
  kpis: {
    completed: number
    delayed: number
    avgEta: number
  }
}
```

**Зачем:**
это даст тебе реальный replay и скраббинг по таймлайну.

# 9. Как использовать PixiJS так, чтобы это не было “лишним”

Очень важный момент. Частая ошибка — “запихнуть Pixi ради Pixi”.

## Как использовать правильно:

Pixi нужен **только для того, что реально выигрывает от canvas/render loop**.

### Хорошие кейсы:

1. **Карта с 20–40 транспортами**, которые двигаются.
2. **Маршруты** и подсветка путей.
3. **Пульсация инцидентов**.
4. **Heatmap загрузки зон**.
5. **Replay**, где объекты меняют положение и статус.

### Плохой кейс:

* рисовать в Pixi обычные карточки/таблицы/формы.

То есть:

* **карта / сцена → Pixi**
* **все панели, фильтры, таблицы, формы → обычный Vue UI**
